## Можливості

XAnalyze сканує сайт, HTML-файл, репозиторій або каталог із кодом і показує точні місця проблем.

- **AI-патерни**: офлайн-, embedding-, гібридний або модельний детектор для користувацького тексту.
- **Символи**: zero-width, homoglyph, незвичайні пробіли, стилізовані літери та типографіка.
- **Аудит сайту**: доступність, SEO, продуктивність, безпека й best practices.
- **Браузерний аудит**: Chromium для клієнтських застосунків і responsive-перевірка на 1440, 834 і 390 px.
- **Факти репозиторія**: tracked або unignored `.env`, конфігурація й коміти, пов'язані з AI-асистентами, blame знахідок.
- **Походження медіа**: IPTC/XMP і необов'язкові C2PA-маніфести. Це факти файлу, не вердикт про пікселі.
- **Історія прогонів**: пауза, продовження, порівняння та документи кожного прогону.
- **Звіт від кожної команди**: `scan`, `audit` і `fullscan` пишуть брифінг і стилізований звіт у теку прогону за датою, і кожен документ починається з того, яка це була команда і з якими параметрами.
- **Один бінарник, три поверхні**: зібраний застосунок при першому запуску пропонує додати команду `xanalyze` у `PATH`, тож CLI і TUI не потребують другого завантаження.

`fullscan` об'єднує перевірки тексту, символів і сайту. Локальний репозиторій сканується статично, якщо не вказано `--devserver`.

Стек визначається за файлами-маркерами або віддамою розміткою. Обидва списки набір тестів звіряє з кодом, тож вони живуть у розділах [Шаблони, які він розуміє](#шаблони-які-він-розуміє) і [Стеки, які він розпізнає](#стеки-які-він-розпізнає), а не переказуються тут.

## Швидкий старт

### GUI для macOS

```bash
curl -L -o XAnalyze.app.zip https://github.com/vlad-demchyk/xAnalyze-/releases/latest/download/XAnalyze.app.zip
unzip XAnalyze.app.zip
mv XAnalyze.app /Applications/
```

Застосунок і командний рядок це один бінарник. При першому запуску вікно
**один раз** пропонує зробити посилання `xanalyze` у `~/.local/bin`, щоб CLI
і TUI працювали в терміналі; відмова запамʼятовується, а те саме
встановлення лишається в Налаштуваннях -> «Команда в терміналі».

### CLI для macOS/Linux

```bash
curl -L -o xanalyze-cli.tar.gz https://github.com/vlad-demchyk/xAnalyze-/releases/latest/download/xanalyze-cli-macos-arm64.tar.gz
tar -xzf xanalyze-cli.tar.gz
echo 'export PATH="$PWD/xanalyze:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

### Із вихідного коду

```bash
git clone https://github.com/vlad-demchyk/xAnalyze-.git
cd xAnalyze-
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

python main.py                         # GUI
python cli.py fullscan https://example.com
```

## Використання

```bash
xanalyze                                      # запустити TUI
xanalyze fullscan https://example.com         # повний аудит сайту
xanalyze scan ./src                           # AI-патерни й символи
xanalyze audit https://example.com --browser  # аудит сайту
xanalyze fix ./src                            # застосувати виправлення символів
xanalyze runs                                 # список і продовження прогонів
xanalyze update                               # перевірити оновлення
xanalyze --version
```

## Команди CLI

### `fullscan`

```bash
xanalyze fullscan https://xformat.net
xanalyze fullscan ./my-project
xanalyze fullscan https://example.com --depth 2 --max-pages 50
xanalyze fullscan https://example.com --breakpoints desktop,mobile
xanalyze fullscan https://example.com --detector hybrid --language uk
xanalyze fullscan https://example.com --styled-report ./reports/site.pdf --report ./reports/agent.md
```

Для URL і HTML браузерний рендеринг увімкнено автоматично, якщо не задано `--no-browser`. Для локального застосунку `--devserver` запускає Node, Django або Rails-сервер.

| Прапорець | Призначення |
|---|---|
| `target` | URL, каталог або HTML-файл |
| `--url` | Примусово трактувати ціль як URL |
| `--depth N` | Глибина обходу URL, за замовчуванням `0` |
| `--max-pages N` | Максимум сторінок, за замовчуванням `30` |
| `--max-files N` | Максимум локальних файлів, за замовчуванням `5000` |
| `--ext ...` | Розширення файлів |
| `--exclude PATTERN` | Додаткове gitignore-виключення |
| `--no-default-excludes` | Не застосовувати стандартні виключення |
| `--repo PATH` | Зв'язати findings рендера з файлами джерела |
| `--devserver` | Запустити dev-сервер репозиторію |
| `--start-command CMD` | Замінити команду запуску сервера |
| `--dev-server-port N` | Порт для Django або Rails |
| `--yes` | Встановлювати відсутні залежності без запиту |
| `--detector NAME` | `offline`, `embedding`, `hybrid`, `llm-judge` |
| `--model NAME` | Модель AI-проходу |
| `--effort LEVEL` | `low`, `medium`, `high` |
| `--no-judgment-cache` | Не використовувати кеш оцінок |
| `--scope NAME` | `content`, `technical`, `both` |
| `--no-typography` | Ігнорувати em dash і curly quotes |
| `--breakpoints NAMES` | `all`, `desktop`, `tablet`, `mobile`, `reflow` (320 px) або список. Без нього браузерний прохід іде на одній ширині, 1440x900 - тій самій, що `desktop` |
| `--styled-report PATH` | PDF або HTML-звіт |
| `--report PATH` | Markdown або JSON-брифінг |
| `--check` | Завершити зі статусом 1 за серйозних проблем |
| `--language LANG` | `uk`, `it`, `en` |
| `--agent` | Підготувати офлайн-кандидатів для агента |
| `--no-browser` | Вимкнути браузерний рендеринг |

### `scan`

```bash
xanalyze scan ./src
xanalyze scan ./src --detector offline --scope content
xanalyze scan ./src --json --check
xanalyze scan ./src --incremental
xanalyze scan ./src --styled-report report.pdf --language uk
```

Корисні опції: `--ext`, `--exclude`, `--max-files`, `--detector`, `--provider`, `--no-unicode`, `--scope`, `--categories`, `--no-typography`, `--no-ignore`, `--json`, `--check`, `--incremental`, `--styled-report`, `--language`. Категорії: `invisible`, `space`, `homoglyph`, `styled`, `typography`.

### `audit`

```bash
xanalyze audit https://example.com
xanalyze audit https://example.com --browser --breakpoints all
xanalyze audit ./page.html --browser
xanalyze audit ./src --category accessibility
xanalyze audit https://example.com --category seo performance
xanalyze audit ./src --fix
xanalyze audit https://example.com --json --report briefing.md
```

Опції охоплюють `--depth`, `--max-pages`, `--max-files`, `--render`, `--exclude`, `--category`, `--language`, `--no-ignore`, `--json`, `--check`, `--ai`, `--provider`, `--fix`, `--report`, `--browser`, `--breakpoints`, `--site-controls`, `--styled-report`. `--site-controls` окремо отримує robots.txt і оголошені в ньому sitemap того ж домену.

Пʼята картка екрана налаштування, **Що показувати**, тримає параметри прогону, які раніше були лише в CLI: шість категорій аудиту (разом із `geo`), поріг певності (`--confidence`) і `--site-controls`. Область (`--scope`) стоїть поруч із контролями репозиторію, а типографіка є категорією символів у Налаштуваннях.

Категорія і певність - це **вигляд над одним готовим проходом**, так само як `--category` і `--confidence`: правила дешеві й ділять один розбір, тому звуження перемальовує список і підсумок, нічого не переаудитуючи, а розширення повертає всі знахідки назад. Експортований звіт пишеться через той самий вигляд, тож екран і файл не можуть розійтися. Коли фільтр ховає все, порожній екран каже це прямо і показує кількість без фільтра, а не звітує сторінку як чисту. `--site-controls` інший за природою - він тягне robots.txt і оголошені в ньому sitemap - тому це вибір прогону, вимкнений за замовчуванням і видимий лише для сайту.

Екран Аудиту в TUI має ті самі три параметри, а списки ширин на екранах Аудиту й Повного сканування містять усі ширини, які знає аудит.

### `fix`, `undo`, `runs`, `resume`, `cache`, `compare`

```bash
xanalyze fix ./src
xanalyze undo ./src
xanalyze runs
xanalyze resume 2026-08-24-1331
xanalyze cache stats
xanalyze cache clear
xanalyze cache path
xanalyze compare ./src
```

`fix` створює `.bak`-копії, `undo` їх відновлює. Стан прогону зберігається для продовження.

### `logs`, `ai`, `clean`

```bash
xanalyze logs --level warning
xanalyze logs --json
xanalyze logs clean
xanalyze ai status
xanalyze ai login
xanalyze ai logout
echo "text" | xanalyze clean --language uk
```

Логи зберігаються у `$XDG_STATE_HOME/xanalyze/logs` або `~/.local/state/xanalyze/logs`. `XANALYZE_LOG_DIR` змінює шлях, `XANALYZE_LOG_LEVEL=debug` вмикає деталізацію.

### `agent-scan` і `agent-judge`

```bash
xanalyze agent-scan ./src --json > passages.json
xanalyze agent-judge ./src --judgments verdicts.json
```

Перша команда видає ID і текст кандидатів, друга застосовує оцінки агента та формує звіт.

Кожен уривок несе поле `language`, і воно дорівнює `null`, коли уривок закороткий, щоб його прочитати. Це відповідь, а не порожнє місце: кнопка з двох слів не стає англійською лише тому, що більше нічого не розпізналось, а агент, якому сказали інакше, судитиме її за чужими очікуваннями.

### `update` і `uninstall`

```bash
xanalyze update
xanalyze uninstall
```

Інтерактивне видалення показує список файлів, які буде прибрано. Неінтерактивний варіант застосовуй лише тоді, коли видалення справді потрібне.

## Шаблони, які він розуміє

Чотирнадцять шаблонних мов мають **пару** фікстур у `tests/fixtures/frameworks`:
той самий компонент, написаний так, як велить його фреймворк, і написаний
неправильно. Правильна половина мусить давати нуль знахідок, зламана - саме ті,
на які заслуговує. Тож це виміряне твердження, а не намір:

`alpine`, `angular`, `blade`, `django`, `erb`, `handlebars`, `liquid`, `php`, `razor`, `react`, `svelte`, `thymeleaf`, `twig`, `vue`

Це те, проти чого скан **перевірено**. Розмітку поза цим списком він усе одно
читає - парсер її не відкидає - але ніщо не довело, що коректний файл у ній
повернеться чистим, і хибну знахідку там набір тестів не спіймає.

## Стеки, які він розпізнає

Проєкт визначається за власними файлами-маркерами, і те, чим він виявився,
вирішує, що вважати чужим кодом, а не написаним тут:

`angular`, `astro`, `bedrock`, `beehiiv`, `carrd`, `craft`, `django`, `docusaurus`, `dotnet`, `drupal`, `eleventy`, `ember`, `flutter`, `gatsby`, `ghost`, `hugo`, `jekyll`, `joomla`, `laravel`, `magento`, `nextjs`, `nuxt`, `qwik`, `rails`, `remix`, `shopify`, `silverstripe`, `spfx`, `spring`, `squarespace`, `statamic`, `storybook`, `sveltekit`, `symfony`, `typo3`, `vite`, `wagtail`, `webflow`, `wix`, `wordpress`, `wordpress-plugin`, `wordpress-theme`

Сигнатури зважуються, а не рахуються: кожна має певність, і платформа
називається лише тоді, коли збіги дають 100, тож маркер, який міг потрапити туди
з іншої причини, мусить підтверджуватись.

## Аналіз

Офлайн-детектор поєднує статистичні сигнали, структуру, кліше й мовні правила. Embedding і модельні детектори додають незалежну оцінку. Кожна знахідка має місце, score, пояснення та рівень певності.

Аудит охоплює `accessibility` (36), `best-practices` (13), `geo` (2), `performance` (8), `security` (10), `seo` (8) - ці числа набір тестів звіряє з реєстром правил. GEO дає лише advisory-сигнали про тип статті, автора й дату, а не прогноз позицій у відповідях ШІ. Статичний режим читає файли; браузерний бачить DOM після рендерингу, клієнтський контент, responsive-стани й заголовки відповіді. `--repo` додає шлях до вихідного файлу для URL-аудиту.


**Правила, що стосуються лише одного роду файлів.** Перевірка виконується там,
де вона щось означає, і ніде більше, а вирішує це доказ, а не прапорець:
синтаксис файла, те, чим документ є за `audit.medium`, і стек, який проєкт
довів на диску.

- **React (`.jsx`, `.tsx`)**: `htmlFor` на мітці, обробник кліку без
  клавіатурного відповідника, статичний елемент, зроблений інтерактивним,
  `tabIndex` там, де немає дії, `autoFocus`, `<a>` з обробником і без адреси,
  та `dangerouslySetInnerHTML`. Компонент ніколи не вважається DOM-елементом:
  `<Button>` не є `<button>`, і те, що він рендерить, є справою компонента.
- **Лист**: перелік шрифтів без загальної родини в кінці, посилання без
  власного кольору і відсутній preheader. Ці правила працюють лише там, де
  документ визначено як лист, а сторінкові правила там не працюють узагалі.
- **WordPress**: змінна шаблону, виведена в розмітку без `esc_html()`,
  `esc_attr()` чи `esc_url()`. Це best practice з позначкою advisory, бо
  статичне читання не бачить, чи значення очистили раніше. Розкладку Bedrock
  розпізнано, тож ядро WordPress у `web/wp/` і таблиці перекладів у
  `web/app/languages/` не аудитуються так, ніби їх написав проєкт.
- **Односторінкові сайти**: посилання на `#секцію`, якої на сторінці немає. Для
  сайту з одного файла це вся навігація, і браузер, коли вона ламається,
  не каже нічого.

**Становий прохід** іде в браузері й перевіряє сторінку в тому стані, в який її ставить людина: індикатор фокуса, клавіатурні пастки, порядок обходу, контент лише на наведення, відкрите модальне вікно з фокусом позаду нього - і подорож формою: поле без доступної назви після виконання скриптів, поле, назване лише placeholder-ом, значення, яке відхиляє сам браузер, і про це ніхто не каже, та текст помилки на екрані, на який не посилається жодне поле. Він читає і не діє: нічого не вписується, не натискається і не відправляється, бо на живому сайті кожна з цих дій запускає власні обробники сторінки. Тому заповнення поля заради перевірки реакції форми лишається поза межами, як і INP, який без справжнього вводу не міряється.

### Сайти за логіном

Половина того, що варто перевіряти, стоїть за входом: адмінка, кабінет, інтранет, стейджинг під базовою автентифікацією. Дві окремі речі, саме в такому порядку.

**Інструмент каже, коли дивиться на двері.** Обхід записує, чи адреса відповіла входом, а не сторінкою - 401 із названою схемою, 403 без неї, перенаправлення на адресу входу, поле пароля в розмітці - і повідомляє це як факт про **прогін**, а не як знахідку про сайт. Одна стіна на сорока адресах - один рядок, а коли все, що прогін прочитав, було стіною, він каже це прямо: чистий підсумок над самими формами входу є найоманливішим виводом, який цей інструмент здатний дати. Той самий абзац несе звіт, бо звіт - це те, що людина передає іншій людині.

**Входите ви самі.** `xanalyze login https://example.com/admin` відкриває справжнє вікно браузера на власній формі сайту; 2FA, SSO і капча працюють, бо це браузер. Інструмент не бачить ні логіна, ні пароля - зберігається лише те, що сайт видав тому браузеру, у профілі з іменем хоста, у власній теці застосунку, з правами лише для вас. Прогони цього хоста далі використовують сесію в **обох** клієнтах: і завантаження, і рендеринг отримують ту саму сесію, інакше браузер бачив би кабінет, а обхід - сторінку входу. `--no-session` читає сайт так, як його бачить сторонній. `xanalyze login --list` показує, що тримає ця машина, `xanalyze login --forget HOST` видаляє одну сесію, і той самий перелік із кнопкою є в Налаштуваннях. Прогін, який ішов із сесією і все одно впав у стіну, каже, що сесія протухла, а не що сайт закритий. У вікні це кнопка **Увійти на сайт**.

Нічого про сесію не потрапляє ні у звіт, ні в журнал, ні в теку прогону, ні в термінал: лише факт і хост, ніколи значення.

**З чого почати.** Прогін по теці відповідає «820 знахідок», і верх цього списку -
ті самі сторінкові правила, повторені в кожному документі. Тому звіт починається
з трьох найважчих речей на **кожен рід** документа - сторінки, компоненти, листи -
за наслідком, а не за кількістю: тека з розсилок і лендінгів читається як два
короткі списки, а не як один довгий.

Знахідки мають рівень `exact`, `needs-browser` або `advisory`. `exact` означає, що розмітка відповідає на питання повністю, `advisory` - що не відповість ніщо і вирішує людина: це редакційне рішення, і саме такими є GEO-ознаки.

**Невизначене не показується.** `needs-browser` - це рушій, який каже, що не зміг визначити: «елемент лежить на фоновому зображенні», «абсолютно позиційований, колір тла не встановити». Заміряно на одній сторінці python.org у справжньому браузері: таких було **312 із 348** знахідок про контраст, а весь прогін після їх виходу дав **182** знахідки замість 497. Звіт, дві третини якого це «ми не знаємо», не є списком, з яким можна працювати, тож прогін називає кількість схованого, а `--unsettled` повертає його. `--confidence exact` - ще суворіший вигляд: він прибирає й редакційні.

Походження медіа читає IPTC/XMP і C2PA. Факти репозиторія охоплюють `.env`, AI-асистентські коміти, конфігурацію та blame. Це provenance, а не твердження, що використання асистента є дефектом.

На обійденому сайті читається **кожне зображення**, на яке посилаються сторінки, а не вибірка. Завантажується лише голова файла - HTTP-range на перші 512 КБ, де й лежать ці поля та розміри в пікселях і де зупиняється пошук C2PA-маркера - тож фотографія на 6 МБ коштує 512 КБ, і після читання в памʼяті нічого не лишається. Зображення з тими самими байтами розпізнаються за хешем, аналізуються один раз і показуються одним записом з переліком місць. Звіт називає, скільки адрес знайдено, скільки прочитано, скільки було повторами і чого не вдалось завантажити: непрочитане зображення не «чисте», воно непрочитане.

### Робота, яку передають шматком чужого сайту

**Тема або плагін WordPress** пізнаються так само, як їх пізнає сам WordPress: за заголовком `Theme Name:` у `style.css` і `Plugin Name:` у головному PHP-файлі плагіна, а не за маркерами інсталяції навколо — у переданої теми їх немає. Її шаблони читаються як фрагменти, тож ніхто не питає в `header.php` канонічного посилання чи `<h1>`: документ там відкривається і закривається у `footer.php`.

**Веб-частина SharePoint** це одне піддерево сторінки, яка належить тенанту. `--within SELECTOR` звужує весь аудит до неї: статичні правила читають лише це піддерево, axe дістає його як `include`-контекст, а HTML_CodeSniffer, становий прохід і виміри вимикаються з надрукованою причиною — кожен із них за побудовою читає цілий документ. Піддерево є фрагментом, яким би не був файл, тож сторінкові правила перестають діяти. Згенерований суфікс у класі чи id — `CanvasZone_9f8e7d`, `root-137` — вводити не треба: селектор повторюється по основі, і прогін каже, яке саме читання спрацювало. Селектор без збігу є помилкою, а не чистою сторінкою.

### Розмітка всередині шаблонного рядка

`.ts`, `.js` і `.mjs` пропускаються як файли: у них `<` є оператором, і `if (a < b)`, віддане HTML-парсеру, стає відкритим тегом, що ковтає решту. Але рядок у зворотних лапках це не код, а класична веб-частина SPFx будує в ньому весь свій інтерфейс. Заміряно на справжньому рішенні SharePoint: так робить 72 із 168 його `.ts`-файлів, і нічого з цього ніколи не читалось, а читання дає 131 знахідку - 60 контролів без доступної назви, 21 зображення без alt, 24 посилання, що відкривають нову вкладку без `rel`. Літерал аудитується як фрагмент, `${...}` стає значенням-заповнювачем, щоб атрибут читався як присутній, а кожна знахідка вказує на рядок, з якого починається літерал.

### Багато веб-частин в одному репозиторії

Рішення SharePoint не є одним артефактом: репозиторії, на яких це заміряно, несуть 30 і 19 веб-частин. Три різні питання, три відповіді: одна частина **як код** (тека і є скоуп, репозиторійний режим так її й читає), одна частина **на сайті** (`--within SELECTOR`), і **частини цього репозиторію по всьому сайту** (`--repo PATH --web-parts`). Якщо репозиторій заданий, а параметра звуження немає, відповіддю лишається весь сайт, а репозиторій служить для того, щоб назвати файл за знахідкою.

`--web-parts` читає маніфести рішення - JSONC із коментарями й висячими комами, тобто те, що пише генератор SPFx - і знаходить кожну частину на сторінці за GUID, який SharePoint кладе в DOM, а якщо його немає, то за основами класів власного CSS-модуля частини. Кожна знахідка називає частину-власника і те, як її знайдено. Сторінка, на якій немає жодної з них, не дає нічого: те, які частини тенант поклав на сторінку, не є справою репозиторію.

### Що прогін лишає незробленим

Перед початком роботи прогін називає глибину, до якої не дійде, і прапорець, який до неї доводить: сайт без `--repo` покаже сторінку, а не файл за нею; репозиторій без `--devserver` не рендериться, тож контраст, порядок фокуса, reflow і всі виміри не виконуються; `--no-browser` і типова одна ширина кажуть те саме про себе. Рядки мають префікс `# [hint]` у stderr, тож агент, що керує CLI, може на них зреагувати прапорцем, а не прийняти поверхневий результат. Це попередження, не запит - скан, що блокується на питанні, не поставиш у конвеєр - і `--no-hints` його вимикає. TUI показує ті самі рядки у журналі прогону.

### Мова звіту

Названа, визначена або англійська, саме в цьому порядку. `--language uk|it|en` вирішує. Без нього вирішують сторінки, але лише коли написані однією з цих трьох: `lang_detect` віддає `other` для мови, для якої тут немає списків, а звіту в `other` не існує - ні підписів, ні перекладів, ні порад. Усе інше - англійська, і прогін каже, що обрав і на скількох читабельних пасажах.

## Звіти й прогони

За замовчуванням документи зберігаються в `~/Desktop/XAnalyze/`; `XANALYZE_REPORT_ROOT` змінює корінь.

```text
XAnalyze/example.com/2026-08-24-0930/
  report.md       згрупований брифінг агента
  report.pdf      звіт для людини
  timings.md      тривалість етапів
  changes.md      порівняння з попереднім прогоном
  state.md        стан для продовження
  state.json      стан для програм
```

```bash
xanalyze fullscan https://example.com --styled-report report.pdf
xanalyze fullscan https://example.com --report briefing.md
xanalyze fullscan https://example.com --json > run.json
```

Звіт групує однакові проблеми й перелічує всі місця. Динамічні ідентифікатори фреймворків нормалізуються лише в атрибутах ідентифікаторів. `changes.md` показує зміни між прогонами; менша кількість findings може означати менший обсяг обходу.

Звіт намальовано власною палітрою XAnalyze, тож одна тяжкість має один колір і тут, і у вікні, і в TUI. Значення несуть рівно дві системи кольорів, і більше жодна:

* **Елементи забарвлені за роллю.** Процитована розмітка підсвічується потегово - орієнтир, інтерактивний контрол, обгортка групування, медіа, текстовий вміст, метадані документа - з легендою, надрукованою один раз і лише для тих ролей, які в цьому звіті справді є. Шість ролей, а не колір на кожну назву тегу: відтінок, що означає «це контрол», запам'ятовується, а хеш назви - ні.
* **Червоне і зелене - це напрямок diff-у, і нічого більше.** Розмітка як є і розмітка як має бути позначені `−` і `+` та пофарбовані відповідно, а проза «як виправити» несе те саме зелене, бо це те саме твердження словами.

Кожна знахідка також називає свою технічну особу одним рядком - ідентифікатор правила, рушій, елемент, скільки рушіїв погодилось, у скількох місцях знайдено, - тож рядок можна знайти, приглушити або звірити з попереднім прогоном просто з надрукованої сторінки. Нічого в документі не скорочується трикрапкою: речення рушія друкується цілим, і назва правила в рейтингу теж.

Недоведена знахідка каже про це в обох документах. `advisory` і `needs-browser` мають бейдж у стилізованому звіті й поле `certainty` в брифінгу агента, і кожна несе речення про те, чим вона **не** є: «це ніхто за вас не перевірить», «відкрийте в браузері». `exact` навмисно не має ні того, ні іншого: документ, де більшість рядків несе позначку певності, вчить читача її пропускати. Обидва факти від початку доходили до вікна і до терміналу і не доходили до двох артефактів, які людина комусь передає.

## Інтерфейси

GUI має налаштування цілі, типу аналізу, детектора, scope, глибини, breakpoint-ів, мови й акаунта. Результати містять список findings, preview, деталі, виправлення та експорт звіту. Механічні виправлення позначені за замовчуванням, модельні чернетки потребують перевірки.

Перша картка, **Що дивимось**, каже, чим виявилась обрана тека. Проєкт розпізнається за власними файлами-маркерами, і те, чим він є, вирішує, що вважати чужим кодом: тепер вікно застосовує ці виключення так само, як завжди робив `xanalyze audit` - та сама тека WordPress раніше давала з вікна сотні знахідок у vendored-ядрі і жодної з CLI. Мовчки це не робиться. Картка називає стек, рахує шляхи, які пропустить, тримає файл-маркер, що довів кожен із них, і пропонує **Сканувати і їх теж** одним кліком, бо профіль - це доказ про власність, а не певність.

Та сама картка несе **Документи - це**, тобто `--medium` у вікні. Типово визначається з розмітки, і це майже завжди правильно; вкажіть вручну для листа, у якого немає ні просторів імен Outlook, ні merge-тегів. На `email` пропускаються браузерні перевірки (canonical, Open Graph, структуровані дані, skip-link, орієнтири, WebP), а перевірки доступності - ні: `image-alt`, `control-name`, `table-headers`, контраст і мова так само реальні в поштовому клієнті, як у браузері.

**Що вікно тепер уміє запитати, а раніше вміла лише командна стрічка.** Три речі, у розширеному ряду:

- **Код за цим сайтом.** Знахідка на сторінці називає сторінку, а сторінка - це де подивитись, а не де правити. Із вказаною текою кожен уривок, який у ній є, отримує файл і рядок: те саме парування `--repo`, що й у CLI, через той самий модуль. Прогін каже, скільки уривків тека пояснила: три з сорока означає не той чекаут - або текст із CMS, - і вікно, яке показало б лише три збіги, про це не сказало б.
- **Лише ця частина сторінки** (`--within`). CSS-селектор веб-частини чи вбудованого віджета: решта документа належить комусь іншому. Те, що всередині селектора, за побудовою є фрагментом, тож сторінкові правила до нього не застосовуються, а селектор, який нічого не знайшов, повідомляється, а не повертається чистим результатом.
- **Максимум файлів у теці** (`--max-files`) у Налаштуваннях. Своєї межі вікно не мало і читало те, що було за замовчуванням, жодного разу не назвавши число, яке обрізало монорепозиторій.

**Перед прогоном вікно тепер каже, чого цей прогін не досягне** - ті самі підказки, що `cli_impl/prerun.py` друкує для CLI, з тих самих даних: тека з кодом не вказана, проєкт міг би показати себе браузеру, браузер вимкнено. Кожна несе дію, якщо вікно її має.

Інкрементного скану у вікні немає. `scan --incremental` перевикористовує кешовані **знахідки** - рядки в JSON без `TextSpan` за ними, - а список у вікні будується зі спанів: для кожного він пропонує переписування, заміну і запис на диск. Кеш дав би там рядки, з якими нічого не зробиш, тож прапорець лишається за CLI і TUI, доки кеш не триматиме спани.

Запуск `xanalyze` без аргументів відкриває TUI з режимами Scan, Audit, Full Scan, Reports, Settings, Account, Update, Uninstall і Logs. Навігація: стрілки, цифрові клавіші, `Tab`, `Esc`, `q`.

**Account** входить у підписку xFormat, не покидаючи термінал. Налаштування завжди пропонували `xformat` як провайдера, а увійти в TUI не було де, тож діяти за цим вибором можна було лише з вікна або через `xanalyze ai login`. Пароль не зберігається: він обмінюється на токен, який лягає в keychain системи, а поле очищується ще до виклику. Інші два провайдери мають власний вхід, і екран каже де саме, замість пропонувати форму, яка не спрацює.

Комірки таблиць переносяться, а не обрізаються. Деталь логу і ціль прогону раніше різав сам екран, що прибирало `key=value`, який пояснював рядок, і **домен**, який ідентифікував прогін.

## Конфігурація

Файл: `~/.config/xanalyze/settings.json`

```json
{
  "ui_language": "uk",
  "llm_provider": "xformat",
  "max_pages": 30,
  "unicode_categories": ["invisible", "space", "homoglyph"],
  "unicode_check_enabled": true
}
```

`.xanalyze-ignore` у корені проєкту використовує gitignore-синтаксис:

```text
vendor/
third_party/
*.min.js
*.min.css
```

Можна додавати секції `[rules]`, `[selectors]`, `[fingerprints]`, а також фрази й шляхи. Коментарі та порожні рядки зберігаються.

## Обмеження

- AI-детекція залежить від корпусу й не доводить авторство; модельні оцінки недетерміновані.
- **Офлайн-прохід по формулюваннях слабкий італійською, і інструмент тепер каже це під час прогону.** На відкладеній половині корпусу він знаходить 36% відомих AI-уривків італійською проти 55% англійською і 71% українською, тоді як embedding-детектор знаходить 100%, 85% і 86%. Прогін, чия сторінка читається як італійська, друкує попередження з назвою кращого детектора і повторює його в JSON як `scan.detector_note`. Прохід по формулюваннях лишається типовим, бо він миттєвий, не потребує `torch`, називає знайдену фразу і вміє замінити її офлайн, а ще ловить чотири відкладені уривки, які embedding пропускає.
- **Детекція тексту працює лише для української, італійської та англійської.** Уривок іншою мовою так і називається, а прохід по формулюваннях і embedding не кажуть про нього нічого, замість того щоб міряти його списками й референсом, які цієї мови не знають. Заміряно на 257 абзацах німецькою, французькою, іспанською, польською і російською: 249 читаються як непідтримувана мова. Перевірки символів, типографіки й аудиту не залежать від мови й працюють далі, а модельний суддя цим обмеженням не зв'язаний.
- Статичний скан не бачить контент, створений під час рендерингу. Використовуйте URL або `--devserver`.
- Один breakpoint не описує responsive-поведінку. Для повної картини використовуйте `--breakpoints all`.
- Типографічна перевірка може знаходити навмисну пунктуацію; її можна вимкнути.
- `--scope technical` міряє символи й технічні сигнали, а не маркетинговий стиль.
- C2PA потребує необов'язкових `c2pa-python` і `cryptography`.
- У 16-колірних терміналах частина кольорів критичності зливається, але текстові підписи лишаються.
