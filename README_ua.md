# XAnalyze

Знаходить текст, написаний моделлю, невидимі символи і дефекти доступності, SEO,
швидкодії та безпеки на сайті, в HTML-файлі або в репозиторії - і називає точний
рядок, а не оцінку.

[English](README.md) | [Italiano](README_it.md)

## Для чого це

Вам дали сторінку, тему, веб-парт або репозиторій, і треба відповісти на три
питання: чи цей текст написала модель, чи є в розмітці символи, яких не дає
жодна клавіатура, і чи ця річ доступна й коректна. XAnalyze відповідає на всі
три за один прогін і називає файл і рядок за кожною відповіддю.

Це один бінарник із трьома поверхнями - вікно, термінальний інтерфейс і
командний рядок - над одним ядром, тож вони не можуть розійтись у тому, що саме
було виміряно.

## Встановлення

**Застосунок для macOS**

```bash
curl -L -o XAnalyze.app.zip https://github.com/vlad-demchyk/xAnalyze-/releases/latest/download/XAnalyze.app.zip
unzip XAnalyze.app.zip && mv XAnalyze.app /Applications/
```

При першому запуску застосунок один раз пропонує покласти себе як `xanalyze` у
`~/.local/bin`, тож CLI і TUI не потребують другого завантаження. Бандл ще не
підписаний: перший запуск - Control-click -> Open.

**Лише CLI**

```bash
curl -L -o xanalyze-cli.tar.gz https://github.com/vlad-demchyk/xAnalyze-/releases/latest/download/xanalyze-cli-macos-arm64.tar.gz
tar -xzf xanalyze-cli.tar.gz && export PATH="$PWD/xanalyze:$PATH"
```

**З вихідників**

```bash
git clone https://github.com/vlad-demchyk/xAnalyze-.git && cd xAnalyze-
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python main.py                                  # вікно
python cli.py fullscan https://example.com      # командний рядок
python cli.py                                   # термінальний інтерфейс
```

## Як користуватись

```bash
xanalyze                                      # термінальний інтерфейс
xanalyze fullscan https://example.com         # усе за один прогін
xanalyze fullscan ./my-project                # те саме по репозиторію
xanalyze scan ./src                           # лише AI-патерни і символи
xanalyze audit ./page.html                    # лише правила сайту
xanalyze fix ./src                            # виправити символи (лишає .bak)
xanalyze runs                                 # список, продовження, порівняння
```

`fullscan` - це відповідь на «перевір оце». URL обходиться і рендериться; тека
читається як вихідний код, якщо `--devserver` не запустить власний сервер
проєкту; один HTML-файл читається як завершена сторінка, якою він і є.

### Команди

| Команда | Що робить |
|---|---|
| `fullscan ЦІЛЬ` | AI-патерни, символи і всі правила сайту, плюс звіти |
| `scan ШЛЯХИ` | AI-патерни і неклавіатурні символи, нічого не змінюючи |
| `audit ЦІЛЬ` | лише правила сайту: URL, HTML-файл або тека |
| `fix` / `undo` | застосувати точні виправлення символів; повернути копії `.bak` |
| `runs` / `resume` / `compare` | прогін є обʼєктом: перелічити, продовжити, звірити з попереднім |
| `login URL` | увійти на сайт власноруч, у справжньому браузері, щоб прогін бачив те, що за дверима |
| `logs` | що прогін насправді робив, у форматі JSON Lines |
| `ai` | акаунт для проходів із моделлю: `status`, `login`, `rewrite` |
| `agent-scan` / `agent-judge` | віддати кандидатів агенту і прийняти його вердикти |
| `clean` | фільтрує текст зі stdin у stdout |
| `update` / `uninstall` | самооновлення з останнього релізу; повне видалення |

`xanalyze КОМАНДА --help` друкує всі параметри. Ті, які варто знати:

| Параметр | Навіщо |
|---|---|
| `--depth N`, `--max-pages N` | як далеко йде обхід і скільки сторінок |
| `--repo ШЛЯХ` | репозиторій за сайтом, щоб знахідка називала файл, а не лише сторінку |
| `--devserver` | запустити власний dev-сервер проєкту і аудитувати відрендерене |
| `--breakpoints all` | аудит на всіх ширинах; без нього одна (1440x900) |
| `--no-browser` | лише статичне читання, і значно швидше |
| `--detector НАЗВА` | `offline` (типово, безкоштовно), `embedding`, `hybrid`, `ai` |
| `--category`, `--confidence` | звузити показане; обидва є видом на один прохід |
| `--within СЕЛЕКТОР` | аудит лише цієї частини сторінки - відданого віджета чи веб-парта |
| `--report ШЛЯХ`, `--styled-report ШЛЯХ` | брифінг для агента (`.md`/`.json`) і звіт для людини (`.pdf`/`.html`) |
| `--json`, `--check` | машинний вивід; код виходу 1 за серйозних знахідок |
| `--language uk\|it\|en` | мова звіту; інакше визначається за сторінками |
| `--project НАЗВА` | один проєкт із теки, де їх кілька: за назвою теки або за шляхом |
| `--start-command КОМАНДА`, `--dev-server-port N` | що запускати замість знайденого скрипта і який порт очікувати |
| `--no-session` | читати сайт так, як його бачить стороння людина, ігноруючи збережений вхід |
| `--profile-defaults` | увімкнути те, що просить розпізнаний стек (див. нижче) |

## Що саме перевіряється

**Текст, написаний моделлю.** Офлайновий прохід читає ритм речень, повторювану
структуру і кліше і називає фразу, яку зіставив, тож із знахідкою можна
сперечатись. Для другої думки є прохід на embedding і прохід із моделлю. Це не
доказ авторства.

**Неклавіатурні символи.** Нульової ширини, гомогліфи, незвичні пробіли,
стилізовані літери і типографські символи - кожен точний і кожен виправляється
на місці.

**Правила сайту** за категоріями, з кількістю, яку стежить набір тестів:

`accessibility` (36), `best-practices` (13), `geo` (2), `performance` (8), `security` (10), `seo` (8)

Правило працює там, де має сенс, і ніде більше, і вирішує це доказ: синтаксис
файла (правила JSX лише в `.jsx`/`.tsx`), призначення документа (правила листа
лише на листі) і стек, який проєкт довів на диску (правило екранування
WordPress лише у WordPress).

**У браузері**, коли він доступний: axe-core і HTML_CodeSniffer, сторінка в
тому стані, у який її приводить людина - індикатор фокуса, клавіатурні пастки,
порядок фокуса, вміст лише під наведенням, відкрите модальне вікно, подорож
формою - і та сама сторінка на кількох ширинах. Він читає і ніколи не діє:
нічого не вводиться, не натискається і не відправляється.

**Походження, а не вирок.** Поля IPTC/XMP і маніфести C2PA у кожному
зображенні, на яке посилається сторінка (завантажуються лише перші 512 КБ), і
факти репозиторія: `.env` під контролем версій, коміти з іменем асистента,
закомічена конфігурація асистента. Це подається як факт про походження, ніколи
як дефект.

**Певність.** Кожна знахідка є `exact`, `needs-browser` або `advisory`.
Невирішене типово не показується - на одній справжній сторінці це було 312 із
348 знахідок контрасту - і прогін каже, скільки лишив поза списком.
`--unsettled` їх повертає, `--confidence exact` прибирає ще й дорадчі.

## Ціль вирішує, що питати

Проєкт оголошує, чим він є, і з цього випливає більше, ніж список тек, які
треба пропустити. Рішення SPFx знає, що віддає веб-парти, і не знає, на який
сайт вони стануть. Застосунок на Vite чи Next, прочитаний із диска, - це
шаблони, яких збірка ще не виконала, де `<App />` не є заголовком. Один
самодостатній HTML-файл нікуди не веде, тож лишається єдина вісь - ширина.

Кожне з цього стає параметром, і кожен приходить зі стеком, який його попросив,
і з файлом-маркером, що цей стек довів: «увімкнено, бо …» є реченням, з яким
можна не погодитись, а не мовчазним дефолтом. **Те, що ви задали самі, не
перезаписується ніколи.**

Вікно і термінальна форма це застосовують: контрол увімкнено, причина під ним,
знімається одним кліком. Командний рядок - ні: він є контрактом, і прогін, що
запустив dev-сервер, бо знайшов `vite.config.ts`, був би не тим прогоном, який
написав автор скрипта. Там ті самі пропозиції друкуються рядками `# [profile]`
у stderr, а `--profile-defaults` просить їх застосувати.

Те саме читання вирішує, які поля взагалі існують: `--depth` потребує адреси,
`--incremental` - файлів на диску, а контрол, який для цієї цілі нічого не
досягає, не показується і не читається, тож `--devserver`, увімкнений для
репозиторія, не піде за вами на один файл.

Тека з кількома проєктами питає, а не зливає їх мовчки: двадцять рішень SPFx в
одній теці - це двадцять артефактів. `--project НАЗВА` і селектор у вікні та в
термінальній формі аудитують один із них окремо, і скан, файл виключень та
dev-сервер ідуть за ним разом, тож вони не можуть описувати різні проєкти.
Репозиторій, який довів щось про себе, лишається одним проєктом: `web/` у
Bedrock - це докрут того ж проєкту, а не другий проєкт.

**У монорепо dev-серверів кілька, і це різні прогони.** Кореневий скрипт `dev`
запускає або оркеструє застосунки під ним, а в кожного застосунку є власний
скрипт. `--devserver` досі обирав мовчки. Тепер прогін каже, який саме
запуститься і що вказаний проєкт запустить власний - заміряно на справжньому
воркспейсі, де корінь оголошує `workspaces: ["apps/*"]`, а кожен із чотирьох
застосунків - свій `dev`. `--start-command` перевизначає скрипт там, де не
підходить жоден.

## Робота, віддана як фрагмент чужого сайту

**Тема або плагін WordPress** розпізнається так, як їх розпізнає сам WordPress
- за заголовком `Theme Name:` у `style.css` і `Plugin Name:` у головному
PHP-файлі, - а її шаблони читаються як фрагменти, тож ніхто не питає з
`header.php` канонічного посилання чи `<h1>`.

**Веб-парт SharePoint** є однією гілкою сторінки, що належить тенанту.
`--within СЕЛЕКТОР` звужує аудит до неї і вимикає, з друкованою причиною, усе,
що за побудовою читає документ цілком. Згенерований суфікс класу (`root-137`)
не треба вписувати: селектор повторюється за основою. `--repo ШЛЯХ
--web-parts` працює в інший бік - читає маніфести рішення і знаходить частини
цього репозиторію всюди, де вони є на сайті.

Розмітка всередині **шаблонного літерала** теж аудитується. `.ts` і `.js`
пропускаються як файли - `<` у них є оператором, - але рядок у зворотних лапках
не є кодом, а класична веб-частина SPFx будує в ньому весь свій інтерфейс.
Заміряно на справжньому рішенні: 72 із 168 `.ts`-файлів і 131 знахідка, яких не
читав ніхто.

## Сайти за логіном

`xanalyze login https://example.com/admin` відкриває справжній браузер на
власній формі сайту. 2FA, SSO і капча працюють, бо це браузер. XAnalyze ніколи
не бачить ні логіна, ні пароля: зберігається те, що сайт віддав тому браузеру,
окремо на кожен хост і читаним лише для вас. `--no-session` читає сайт так, як
його бачить стороння людина; `login --list` і `login --forget ХОСТ` керують
збереженим. Нічого про сесію не потрапляє ні у звіт, ні в журнал, ні в термінал.

Обхід також фіксує, коли адреса відповіла дверима, а не сторінкою, і каже про
це прямо: чистий підсумок по самих лише формах входу є найоманливішим виводом,
який цей інструмент може дати.

## Звіти

Кожна команда пише теку прогону за датою, типово в `~/Desktop/XAnalyze/`
(`XANALYZE_REPORT_ROOT` змінює місце):

```text
XAnalyze/example.com/2026-09-02-0930/
  report.md     згрупований брифінг для агента
  report.pdf    звіт для людини
  timings.md    час етапів
  changes.md    що змінилось від попереднього прогону
  state.json    стан для продовження
```

Кожен документ починається з того, яка це була команда і які параметри змінили
виміряне. Повторювана проблема перелічена один раз, а її місця вкладені під
нею. `--json` зберігає кожну знахідку - для CI.

## Інтерфейси

**Вікно** (`python main.py` або застосунок). Екран налаштування цілі й прогону,
далі список знахідок поруч із превʼю вихідного коду або відрендереної сторінки,
з виправленнями, оглядом замін і експортом звіту. Дві ширини можна вивести
одночасно, щоб закрити питання «це ламається лише на мобільному».

**Термінал** (`xanalyze` без аргументів). Scan, Audit, Full Scan, Reports,
Settings, Account, Update, Logs. Стрілки, цифрові скорочення, `Tab`, `Esc` і
`Ctrl+R` для запуску.

Механічні виправлення позначено типово; чернетки моделі завжди потребують
перегляду; рішення на кшталт альтернативного тексту до фотографії ніколи не
подаються як автоматичне виправлення.

## Конфігурація

Налаштування живуть у `~/.config/xanalyze/settings.json` - мова, провайдер,
`max_pages`, категорії символів.

`.xanalyze-ignore` у корені проєкту використовує синтаксис gitignore і вміє
глушити за правилом, селектором або відбитком:

```text
vendor/
*.min.js

[rules]
meta-viewport

[fingerprints]
083bea550659aadb
```

## Шаблони, які він розуміє

Чотирнадцять шаблонних мов мають **пару** фікстур у
`tests/fixtures/frameworks`: той самий компонент, написаний так, як велить його
фреймворк, і написаний неправильно. Правильна половина не має давати знахідок,
а зламана - має давати саме потрібні, тож це заміряне твердження:

`alpine`, `angular`, `blade`, `django`, `erb`, `handlebars`, `liquid`, `php`, `razor`, `react`, `svelte`, `thymeleaf`, `twig`, `vue`

Розмітку поза цим списком він усе одно читає - парсер її не відкидає, - але
ніщо не довело, що коректний файл у ній повертається чистим.

## Стеки, які він розпізнає

Проєкт визначається за власними файлами-маркерами, і те, чим він виявився,
вирішує, що вважати чужим кодом, а не написаним тут:

`angular`, `astro`, `bedrock`, `beehiiv`, `carrd`, `craft`, `django`, `docusaurus`, `dotnet`, `drupal`, `eleventy`, `ember`, `flutter`, `gatsby`, `ghost`, `hugo`, `jekyll`, `joomla`, `laravel`, `magento`, `nextjs`, `nuxt`, `qwik`, `rails`, `remix`, `shopify`, `silverstripe`, `spfx`, `spring`, `squarespace`, `statamic`, `storybook`, `sveltekit`, `symfony`, `typo3`, `vite`, `wagtail`, `webflow`, `wix`, `wordpress`, `wordpress-plugin`, `wordpress-theme`

Розпізнавання є доказом: профіль називає файл, який його довів, виключення
проголошуються, а не застосовуються мовчки, і одним кліком їх можна скасувати.

## Межі

- Виявлення AI-тексту залежить від корпусу. Це не доказ авторства, а судження
  моделі не є детермінованими.
- **Виявлення тексту охоплює лише українську, італійську й англійську.**
  Пасаж іншою мовою так і називається і лишається без оцінки, замість міряння
  списками, які цієї мови не знають. Перевірки символів і сайту не залежать
  від мови.
- **Офлайновий прохід слабкий італійською**: на відкладеній половині корпусу
  він знаходить 36 % відомих AI-пасажів проти 55 % англійською і 71 %
  українською, тоді як embedding знаходить 100 %, 85 % і 86 %. Прогін по
  італійських сторінках каже про це і називає кращий детектор.
- Скан теки не бачить вмісту, який зʼявляється лише після рендерингу.
  Використовуйте URL або `--devserver`.
- Одна ширина не описує адаптивну поведінку. Використовуйте `--breakpoints all`.
- Типографські перевірки можуть позначити навмисну пунктуацію
  (`--no-typography`).
- Читання C2PA потребує необовʼязкових `c2pa-python` і `cryptography`.

## Збірка релізу

```bash
make version        # що каже config.py
make rebuild-all    # обидва бандли на цій версії
make package        # два архіви, які шукає `xanalyze update`
```

`make package` відмовляється працювати над застарілим бандлом. Жоден архів поки
не підписаний і не нотаризований.

## Вимоги
